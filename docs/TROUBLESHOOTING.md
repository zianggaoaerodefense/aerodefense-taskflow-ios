# Troubleshooting Guide

Common problems and fixes for the Daily Workflow Management App.

---

## Git / Setup Issues

### `git clone` returns 403 Forbidden

**Cause:** Using a password instead of a personal access token, or the token has expired.

**Fix:**
1. Create a personal access token: GitHub → Settings → Developer settings → Personal access tokens → Generate new token.
2. Clone using the token: `git clone https://<your-token>@github.com/your-org/daily-workflow-app.git`
3. Or use SSH: `git clone git@github.com:your-org/daily-workflow-app.git`

### Expired GitHub token

**Symptom:** `git push` or `git pull` returns 401 or 403.

**Fix:** Generate a new personal access token and update your git credentials (or `~/.netrc` or the keychain entry).

## Expo App Issues

### QR code not opening in Expo Go

**Cause 1:** Phone and computer are on different networks.

**Fix:** Start Expo with tunnel mode: `npx expo start --tunnel`

**Cause 2:** Expo Go is outdated.

**Fix:** Update Expo Go from the App Store or Google Play.

**Cause 3:** The Expo dev server is not running.

**Fix:** Confirm `npx expo start` is running and the terminal shows the QR code.

### App loads but shows a blank screen or "Something went wrong"

**Cause:** Missing or incorrect environment variables.

**Fix:**
1. Confirm `app/.env` exists (not just `app/.env.example`).
2. Confirm `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` are filled in.
3. Stop the dev server and restart: `npx expo start --clear`

### "Unable to resolve module" error

**Cause:** Missing or corrupted `node_modules`.

**Fix:**
```bash
cd app
rm -rf node_modules
npm install
npx expo start --clear
```

### Expo dev server stops working when computer goes to sleep

**Cause:** The Expo development server runs on your local machine. If the machine sleeps, turns off, or loses network, the dev server stops.

**Fix:** Keep your machine running, or use EAS Build for a standalone app that does not depend on your local server.

### "Network request failed" when the app tries to load data

**Cause 1:** Supabase URL is incorrect.

**Fix:** Check `EXPO_PUBLIC_SUPABASE_URL` in `app/.env`. It should look like `https://your-project-ref.supabase.co`.

**Cause 2:** The `public` schema is not exposed in the Supabase dashboard.

**Fix:** Go to Supabase dashboard → Settings → API → Exposed schemas. Make sure `public` is in the list.

## Supabase Authentication Issues

### "Email not confirmed" error on sign-in

**Cause:** Email confirmation is enabled in Supabase Auth settings.

**Fix (development):** Go to Supabase dashboard → Authentication → Providers → Email → Disable "Confirm email". Re-enable before shipping to real users.

**Fix (production):** The user must click the verification link sent to their email.

### Sign-up succeeds but sign-in fails

**Cause:** Session not persisting, or SecureStore issue on the device.

**Fix:**
1. Make sure `expo-secure-store` is installed: `cd app && npm install expo-secure-store`.
2. Rebuild the app: `npx expo start --clear`.
3. On Android emulator, ensure Google Play Services are available (required for the Android Keystore).

### "Invalid JWT" or "JWT expired"

**Cause:** The session token has expired and auto-refresh failed.

**Fix:** Sign out and sign back in. If this happens repeatedly, check that `autoRefreshToken: true` is set in the Supabase client configuration (`app/lib/supabase.ts`).

## Supabase Data Issues

### Tasks not showing in the app after agent writes them

**Cause 1:** Supabase Realtime subscription is not active.

**Fix:** Confirm that Realtime is enabled on the `tasks` table in the Supabase dashboard → Database → Replication.

**Cause 2:** RLS policy is blocking the user from reading their own tasks.

**Fix:** Run this in the Supabase SQL Editor to check policies:
```sql
SELECT tablename, policyname, cmd, qual
FROM pg_policies
WHERE schemaname = 'public' AND tablename = 'tasks';
```
The `qual` column should show `auth.uid() = user_id`.

**Cause 3:** Agent wrote tasks with the wrong `user_id`.

**Fix:** Check `audit_logs` or `task_events` in the Supabase dashboard to see which `user_id` was used. The agent token should resolve to the correct `user_id` — verify the token was generated by the correct user account.

### RLS blocks all data (user sees nothing)

**Cause:** RLS is enabled but no SELECT policy allows the user to read their rows.

**Fix:** Run the migration again, or manually add the policy:
```sql
CREATE POLICY "users_select_own" ON tasks
  FOR SELECT USING (auth.uid() = user_id);
```

### RLS allows too much data (user sees other users' rows)

**Cause:** An overly broad policy (`USING (true)` or `USING (auth.role() = 'authenticated')`).

**Fix:** Replace with a `user_id`-scoped policy:
```sql
DROP POLICY "overly_broad" ON tasks;
CREATE POLICY "users_select_own" ON tasks
  FOR SELECT USING (auth.uid() = user_id);
```

### Agent wrote data with wrong user_id

**Cause:** The agent token maps to a different user than expected, or `user_id` was incorrectly taken from the request body.

**Fix:**
1. Revoke the token in the app and generate a new one.
2. Verify the Edge Function resolves `user_id` from the token hash lookup, not from the request body.
3. Check `agent_connections` to confirm which user the token belongs to.

### Service role key accidentally used in client

**Symptom:** App has access to all users' data; RLS appears to be bypassed.

**Fix:**
1. Remove the service role key from the client-side code immediately.
2. Rotate the service role key in the Supabase dashboard → Settings → API → Reset service role key.
3. Update the key in all server-side environments.
4. Audit what data may have been exposed.

## Edge Function Issues

### Edge Function returns 401

**Cause 1:** `X-Agent-Token` header is missing or incorrect.

**Fix:** Verify the token was copied correctly from the app. Tokens are 64-character hex strings.

**Cause 2:** The agent connection was revoked.

**Fix:** Generate a new agent connection token in the app.

**Cause 3:** The token has expired (if `expires_at` was set).

**Fix:** Revoke and generate a new token.

### Edge Function returns 500

**Cause:** Internal server error in the Edge Function.

**Fix:** Check Edge Function logs in the Supabase dashboard → Edge Functions → Logs.

### Edge Function not deployed

**Symptom:** 404 when calling the function URL.

**Fix:**
```bash
supabase functions deploy agent-context
supabase functions deploy agent-write
supabase functions deploy agent-update-task
supabase functions deploy create-agent-connection
supabase functions deploy revoke-agent-connection
```

## Expo Go vs. TestFlight vs. Production

| | Expo Go | TestFlight | App Store |
|---|---------|-----------|-----------|
| **Purpose** | Development and testing | Beta testing | Public release |
| **Requires** | Expo Go app + dev server | Apple Developer account ($99/yr) | Apple Developer account + review |
| **Works without local server** | No | Yes | Yes |
| **Updates** | Instant (scan QR code) | OTA with EAS Update, or new build | App store submission + review |
| **Suitable for real users** | No | Yes (beta) | Yes |

For production, use [EAS Build](https://docs.expo.dev/eas/).

## Still Stuck?

1. Check the Supabase logs: Dashboard → Logs → API/Edge Functions.
2. Run the sanity check script: `bash scripts/sanity-check.sh`.
3. Check `docs/SETUP_APP.md`, `docs/SETUP_DATABASE.md`, and `docs/SETUP_AGENT.md`.
4. Open an issue on GitHub with:
   - Which step in the setup guide you are on
   - The exact error message
   - Your OS and Node.js version (`node --version`)
   - Whether you are using local Supabase CLI or a hosted Supabase project
